# PersonaPlex MLX Real-Time Server

This directory contains the MLX-accelerated real-time WebSocket server for PersonaPlex, enabling full-duplex speech-to-speech interaction on Apple Silicon.

## Overview

`server_mlx.py` is the MLX port of `moshi/moshi/server.py`, providing:

- **Apple Silicon GPU acceleration** via MLX framework
- **Real-time audio streaming** using WebSocket protocol
- **Full-duplex operation** (simultaneous listening and speaking)
- **Voice prompt support** (.pt embeddings or .wav audio)
- **Text prompt injection** for personality customization
- **Identical client compatibility** (same WebSocket protocol as PyTorch server)

## Architecture

### Key Components

1. **ServerState**: Manages audio tokenizers, text tokenizer, and LM generator
   - `mimi` / `other_mimi`: rustymimi.Tokenizer instances for audio encoding/decoding
   - `text_tokenizer`: sentencepiece for text token processing
   - `lm_gen`: PersonaPlexLmGen wrapper for MLX inference

2. **WebSocket Handler** (`handle_chat`):
   - Parses client requests (voice prompt, text prompt, seed)
   - Loads and caches voice prompts
   - Runs system prompt pipeline (voice → silence → text → silence)
   - Orchestrates three async loops: recv, opus processing, send

3. **Opus Processing Loop**:
   - Receives PCM chunks from client
   - Accumulates to frame_size (1920 samples = 80ms @ 24kHz)
   - Encodes user audio with rustymimi
   - Runs MLX inference (PersonaPlexLmGen.step)
   - Decodes agent audio with rustymimi
   - Sends audio and text tokens back to client

### MLX-Specific Adaptations

- **Unified memory**: No explicit CPU↔GPU transfers
- **Minimal synchronization**: Single `mx.eval()` after warmup
- **Async-friendly**: Long-running operations wrapped in `asyncio.to_thread()`
- **NumPy bridges**: rustymimi I/O stays in NumPy, only inference uses MLX arrays

## Usage

### Basic Command

```bash
python -m moshi_mlx.server_mlx \
    --hf-repo nvidia/personaplex-7b-v1 \
    --host 0.0.0.0 \
    --port 8998
```

This will:
1. Download MLX weights (`personaplex_mlx.safetensors`) from HuggingFace
2. Download rustymimi tokenizer weights
3. Download sentencepiece text tokenizer
4. Download voice prompts archive (`voices.tgz`)
5. Download web UI static files (`dist.tgz`)
6. Start server on port 8998

### Advanced Options

```bash
python -m moshi_mlx.server_mlx \
    --moshi-weight /path/to/personaplex_mlx.safetensors \
    --mimi-weight /path/to/mimi.safetensors \
    --tokenizer /path/to/tokenizer_spm_32k_3.model \
    --voice-prompt-dir /path/to/voices \
    --static /path/to/dist \
    --host 0.0.0.0 \
    --port 8998 \
    --temp-audio 0.8 \
    --temp-text 0.7 \
    --topk-audio 250 \
    --topk-text 25 \
    --max-steps 3000
```

### HTTPS with SSL

```bash
python -m moshi_mlx.server_mlx \
    --hf-repo nvidia/personaplex-7b-v1 \
    --host 0.0.0.0 \
    --port 8998 \
    --ssl /path/to/ssl/certs
```

The SSL directory must contain:
- `key.pem`: Private key
- `cert.pem`: Certificate

### Gradio Tunnel (for remote access)

```bash
python -m moshi_mlx.server_mlx \
    --hf-repo nvidia/personaplex-7b-v1 \
    --gradio-tunnel \
    --gradio-tunnel-token my-secret-token
```

## WebSocket Protocol

The server implements the same protocol as the PyTorch server for client compatibility:

### Client → Server

- **Handshake**: Wait for server to send `b"\x00"` after connection
- **Audio**: Send `b"\x01" + opus_bytes` for each audio packet

### Server → Client

- **Handshake**: `b"\x00"` sent after system prompts complete
- **Audio**: `b"\x01" + opus_bytes` for agent audio stream
- **Text**: `b"\x02" + utf8_bytes` for agent text tokens (word-by-word)

### Query Parameters

Send as URL query string to `/api/chat?param=value`:

- `voice_prompt`: Filename (e.g., `NATF2.pt`) or empty for default
- `text_prompt`: System text prompt (e.g., "You are a helpful assistant")
- `seed`: Random seed for reproducibility (-1 or omit for random)

## Voice Prompts

Voice prompts define the agent's speaking style and persona.

### Format Options

1. **Pre-computed embeddings (.pt)**:
   - Fast loading (no audio encoding needed)
   - Contains transformer embeddings + KV cache state
   - Generated by Stage 3 (voice prompt system)
   - Example: `NATF2.pt`, `s0.pt`

2. **Audio files (.wav)**:
   - 24kHz mono WAV files
   - Normalized to -24 LUFS during loading
   - Encoded frame-by-frame with rustymimi
   - Slower than .pt but more flexible

### Directory Structure

```
voices/
├── NATF2.pt              # Pre-computed female voice
├── s0.pt                 # Pre-computed male voice
├── custom_voice.wav      # Custom audio prompt
└── ...
```

## Text Prompts

Text prompts customize the agent's personality and behavior.

### Format

Text prompts are automatically wrapped with `<system>` tags:

```
Input:  "You are a helpful assistant"
Wrapped: "<system> You are a helpful assistant <system>"
```

### Examples

- **Friendly teacher**: "You are a wise and friendly teacher. Answer questions clearly."
- **Technical expert**: "You are a technical expert. Provide detailed, accurate answers."
- **Conversational**: "You enjoy deep conversations about philosophy and technology."

## Performance Considerations

### Warmup

The server runs a 4-frame warmup loop on startup to:
- Prime MLX compilation caches
- Allocate memory buffers
- Pre-compile kernels

Warmup takes ~5-10 seconds on first run, faster on subsequent runs.

### Real-Time Requirements

For 80ms frames @ 24kHz:
- **Target latency**: <80ms per frame (12.5 fps)
- **MLX inference**: ~30-50ms on M1/M2/M3 (fp16)
- **Audio I/O overhead**: ~5-10ms (opus encoding/decoding)
- **Network latency**: Variable (depends on connection)

### Memory Usage

- **Model**: ~7GB (fp16)
- **KV cache**: ~500MB (max_steps=3000)
- **Audio buffers**: <100MB

Total: ~7.5-8GB recommended

## Troubleshooting

### Server won't start

1. **Check MLX installation**:
   ```bash
   python3 -c "import mlx.core as mx; print(mx.__version__)"
   ```

2. **Verify weights exist**:
   ```bash
   ls ~/.cache/huggingface/hub/models--nvidia--personaplex-7b-v1/
   ```

3. **Check port availability**:
   ```bash
   lsof -i :8998
   ```

### Client connection fails

1. **Verify server is listening**:
   ```bash
   curl http://localhost:8998/
   ```

2. **Check firewall rules** (if using 0.0.0.0)

3. **Try without SSL first** (eliminate certificate issues)

### Audio quality issues

1. **Reduce sampling temperature**:
   ```bash
   --temp-audio 0.6 --temp-text 0.5
   ```

2. **Increase top-k** (more conservative sampling):
   ```bash
   --topk-audio 500
   ```

3. **Check voice prompt quality** (try different .pt files)

### Out of memory

1. **Reduce max_steps**:
   ```bash
   --max-steps 2000
   ```

2. **Close other applications** (free GPU memory)

3. **Use lower precision** (not yet implemented, fp16 is minimum)

## Comparison with PyTorch Server

| Feature | PyTorch (`server.py`) | MLX (`server_mlx.py`) |
|---------|----------------------|----------------------|
| Backend | torch + MimiModel | mlx + rustymimi |
| Device | CUDA GPU | Apple Silicon GPU |
| Memory | Explicit CPU↔GPU | Unified memory |
| Sync | `torch.cuda.synchronize()` | `mx.eval()` (sparse) |
| Audio codec | PyTorch MimiModel | rustymimi Tokenizer |
| LM wrapper | LMGen | PersonaPlexLmGen |
| Protocol | WebSocket | WebSocket (identical) |
| Client | Same client works | Same client works |
